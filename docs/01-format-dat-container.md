# 01 · DAT 容器 / 加密 / 分帧格式

> 本文只描述**格式与流程**，不含密钥、不含固件数据。
> 示意图：`diagrams/01-dat-container.svg`、`diagrams/02-unpack-pipeline.svg`

## 1. 容器层

```
偏移 0         : 89 55 46 55 0D 0A 1A 0A        (8 B 魔数)
偏移 8 起      : 记录流，可重复 N 次
末尾 12 字节   : u32be(4) + "DEND" + u32be(CRC32)
```

### 记录结构

```
[u32be size] [4 B ASCII type] [data, size 字节]
```

`size` 只计 `data` 部分，不含头部的 8 字节。

### 记录类型命名

4 字节 ASCII，形如 `0700_part_image`：

- 前 4 位数字 = 编号（决定处理顺序）
- 后缀 = 语义名

常见类型：

| 类型 | 含义 |
|---|---|
| `0000_*` | 包元信息 |
| `0100_*` | 主数据段 |
| `0110_backup` | 备份分区载荷（含 `MainDest.txt`：平台名 / 机型代号 / 文件名） |
| `0300_partconf` | 分区配置（`partinf.conf`，30 条记录） |
| `0700_part_image` | 分区镜像 |
| `08xx_*` | 机型设置（含 `kemco.txt`：真实内核 cmdline） |

**设计性质**：记录互相独立、长度自描述 ⇒ 可以**只取需要的记录**，不必解密整包。

## 2. 加密层

按**位置**切分两种算法，不是按记录切分。

| 区间 | 算法 | 性质 |
|---|---|---|
| 前 512 B | AES-128-ECB | 全平台一把 `key_aes`；位置、长度固定；与机型无关 |
| 其余部分 | AES-256-CBC | 机型密钥；IV 取自 DAT 偏移 `N - 0x110` |

**容器中不含任何密钥字段。** 密钥来自设备侧，不与包一起分发。

## 3. 分帧层

解密后得到的是**定长帧流**，不是连续数据。

```
每帧固定 1024 B：
  +0    u16  checksum      (小端)
  +2    u16  sizeAndEnd    (小端；bit15 = 本帧是末帧)
  +4    payload            (最多 1020 B)
  剩余  0xFF 填充
```

`checksum` 计算方式：把从帧内 `+2` 起的 **511 个小端 u16** 求和，取低 16 位。

ZV-E10 实测：**363,725 帧 × 1024 B + 272 B 尾部**。

### 尾部

末尾 272 B 不在帧流中，**不参与帧校验**。

> **必须原样复制，绝不可重新加密。**
> 它被后续环节使用；重新加密会破坏下游处理，而且不会有任何校验提前报错 ——
> 这正是回打包最容易踩的坑。

## 4. 载荷头

帧流还原后的明文以一个头开始：

```
+0x00  "UDTRFIRM"
+0x24  机型 ID
+0x30  fwOffset（ZV-E10 = 0x24200）
```

`fwOffset` 处是一个 **ustar 归档**（ZV-E10 共 174 条目）。

## 5. 完整链路

```
DAT → [容器解析] → 记录流
    → [两段解密] → FDAT 明文
    → [分帧还原] → UDTRFIRM 载荷
    → [定位 fwOffset] → ustar tar
    → [解 tar] → 分区镜像
    → [挂载/解包] → 根文件系统
```

反向即为打包顺序。回打包的强制约束见 `02-integrity-checks.md` 末节。
